# GPT: THE ATLAS OF KNOWLEDGE

> **中文名称：** GPT：知识宇宙图鉴  
> **项目类型：** 程序化动画 / 知识可视化 / 音乐视觉艺术 / 交互式网页  
> **文档版本：** v1.0（项目策划案）  
> **参考项目：** [Nyankomintsu/world-execute-me-lyric-mv](https://github.com/Nyankomintsu/world-execute-me-lyric-mv)  
> **建议成片时长：** 3 分 30 秒  
> **目标规格：** 16:9，1080p60 预览 / 4K60 最终成片  
> **项目性质：** 非官方原创数字艺术与科普项目，非 OpenAI 官方产品

---

## 项目摘要

**如果人类积累的知识能够变成一个可见的宇宙，那么 GPT 会如何帮助我们探索它？**

本项目参考 `world-execute-me-lyric-mv` 的程序化 MV 制作方法，以一次虚构的 GPT 对话为叙事入口，把数学、物理、化学、生命、历史、语言、艺术和计算机等领域组织成能够相互转换、彼此连接的视觉世界。作品从一枚光标开始，穿越各学科意象，汇聚为庞大的知识网络，随后呈现知识边界，并回到人类的下一次提问。

项目最终形成两个交付形态：

1. **3 分 30 秒左右的音乐视觉短片**：以可重复渲染的程序化动画制作。
2. **可交互的知识宇宙网页**：允许观众浏览概念节点、关系和参考来源。

**核心原则：** 本项目表现的是“GPT 可以帮助人类探索的知识世界”，并非真实导出 GPT 的训练语料、模型参数、内部表征、实时推理过程或全部知识。所有视觉效果应明确区分**有来源的知识数据**与**艺术化模拟**。

## 一、参考项目核心拆解

### 1.1 原项目概述

参考仓库是为 Mili 的《world.execute(me);》制作的非官方歌词 MV 工程。第四版将整首作品处理为 Claude 与用户之间的一场对话。用户仅以鼠标光标、消息、输入状态和在线状态出现，Claude 由人物剪影及界面元素代表。

原项目把画面划分为三类：

| 原项目画面形式 | 功能 | 对本项目的启发 |
| --- | --- | --- |
| **Interface（界面）** | 显示用户所能看到的消息、状态和操作 | 构建 GPT 提问、回答与探索界面 |
| **Plate（版画）** | 用剪影、符号、形状和巨大字体呈现抽象意象 | 用不同学科的可识别符号构建章节主视觉 |
| **Code（代码）** | 用命令行、代码和循环等形式表现特定剧情段落 | 在“关联与计算”段落用程序语法表达抽象的数据处理 |

其重要特征不是界面仿真，而是：**每一处视觉元素、色彩变化和画面切换都服务于叙事。**

### 1.2 原项目的技术构成

README、`docs/v4/PLAN.md`、`docs/v4/KIT.md`、`package.json` 和 `STORYBOARD.md` 表明，原项目采用：

- **时间驱动的确定性动画：** `renderFrame(t)` 以歌曲时间控制单帧渲染，同一时间点可重现对应的画面。
- **Canvas 2D + WebGL2：** 浏览器绘图、合成及后处理。
- **音频数据预处理：** 音乐节拍、起音、响度等分析结果作为动画驱动数据。
- **镜头清单与自动分镜：** 场景包含时间、歌词区间、叙事时刻、布局、色彩状态、转场和渲染函数。
- **无头浏览器与 FFmpeg 导出：** 通过 Playwright 驱动浏览器逐帧导出，生成视频。
- **测试与质量检查：** 音画同步、闪烁、回归截图和镜头覆盖检查。

仓库第四版提供 87 镜头的自动分镜表，支持 1080p60 预览及 4K60 导出流程。

### 1.3 必须保留的五项思想

1. **让数据驱动画面，而不是堆砌特效。** 每个镜头必须对应确定的知识主题或叙事事件。
2. **同一套视觉语法贯穿整部作品。** 比如颜色代表学科，节点代表概念，连线代表可说明的关系。
3. **按时间直接求出画面。** 支持任意时刻定位、修改和复现，降低迭代成本。
4. **美术设计与工程实现解耦。** 通过场景模块、色板、音频时间表和公共组件组织工程。
5. **建立严格的制作与验收闭环。** 从分镜、单镜预览、音乐同步到输出检查均可执行验证。

### 1.4 不应照搬的部分

不直接复刻原项目的 Claude 人物设定、聊天剧情、歌手作品、歌词内容、角色美术、镜头或画面构图。本项目必须具备原创叙事、原创视觉资产与独立的知识内容组织方式。参考仓库中不同资产有不同授权：代码及自产文档为 MIT，角色剪影及其相关画面另有 CC BY-NC-SA 4.0 限制，歌曲与歌词独立归权利人所有。使用前需要逐项核对。

**可继承的是制作方法；需要原创的是故事与画面。**

## 二、作品定位与知识表达边界

### 2.1 三个表达层次

**知识世界（What）**：呈现数学、自然科学、人文、艺术、计算机等概念和经典问题。

**知识联系（How they connect）**：表现跨学科关联，如傅里叶变换与音乐、医学成像和图像处理的联系。

**知识边界（What remains uncertain）**：通过未验证节点、缺失来源及断裂连线，表达语言模型可能回答错误、知识可能过时、部分问题尚无定论等事实。

### 2.2 真实数据与艺术表达的区分

| 内容 | 数据属性 | 画面表达 |
| --- | --- | --- |
| 真实知识概念 | 人工精选、标注来源 | 可点击的正式知识节点 |
| 学科关联 | 具备来源或合理说明 | 标有关系类型的正式连线 |
| 氛围星云、粒子 | 程序生成、纯视觉 | 不应计作真实知识数量 |
| 旁白与 AI 对话 | 创作脚本 | 明确为虚构情境 |
| 知识灰区 | 已知的不确定性主题 | 不等同于测得 GPT 内部缺口 |
| 概念查询动画 | 前端演示或应用级流程 | 不冒充模型真实内部推理轨迹 |

作品应避免使用“完整 GPT 知识库地图”“真实参数空间可视化”等不准确描述。更加准确的名称是**GPT 主题知识宇宙可视化**。

## 三、创作概念与叙事设定

### 3.1 核心问题

> **What do you know about our world?**  
> 你对我们的世界了解多少？

以一次虚构的人机对话为引子：用户输入一个问题，屏幕上的光标转化为发光粒子，穿越数学、物理、生命与文明。知识由孤立概念形成复杂网络；镜头抵达宏大高潮后发现未知与不确定，最终所有线条回归输入框。

结尾提出：

> **What would you like to discover?**  
> 接下来，你想探索什么？

### 3.2 叙事结构

**人类提出问题 → 知识诞生 → 学科扩展 → 跨领域连接 → 认识局限 → 回归探索。**

叙事不把 GPT 拟人化为无所不知的生命，而是将其塑造成一种帮助用户连接知识、解释概念、发现问题的工具。

### 3.3 核心情绪曲线

| 阶段 | 情绪 | 音画节奏 |
| --- | --- | --- |
| 唤醒 | 神秘、克制 | 静默与低频脉冲 |
| 学科展开 | 惊奇、秩序 | 节奏逐步增加 |
| 文明与创造 | 丰富、温暖 | 多种视觉元素交织 |
| 知识汇聚 | 宏大、震撼 | 全片强节奏高潮 |
| 知识边界 | 平静、反思 | 降低音量与画面密度 |
| 回归问题 | 开放、希望 | 单一光点与静止光标 |

## 四、视觉美术规范

### 4.1 总体视觉风格

以**深色宇宙 + 科学图形 + 版画质感 + 程序化几何**作为基础体系。避免将画面做成无组织的点云特效合集。

- **背景层：** 深色空间、微弱纹理、局部雾化，不使用纯黑平涂作为唯一背景。
- **主体层：** 每镜只有一个首要知识概念或明确空间焦点。
- **信息层：** 少量公式、名称、坐标、命令行、时间线、标注和字幕。
- **摄影机：** 以推进、拉远、轨道绕行、穿行和无缝变形为主。
- **质感：** 在关键主题画面中引入丝网印刷、半色调、错位版画和剪纸感，适当使用发光。

### 4.2 学科颜色方案（建议值）

| 视觉角色 | 建议颜色 | 用途 |
| --- | --- | --- |
| 背景 | `#090E18` | 知识宇宙空间 |
| 数学与逻辑 | `#61C8F2` | 公式、几何与函数 |
| 物理 | `#83A8FA` | 波动、粒子与天体 |
| 生命科学 | `#79D6A0` | 分子、DNA、生命之树 |
| 历史与文明 | `#E5B870` | 时间轴、建筑与文字 |
| 艺术与文学 | `#CDA2FF` | 音符、书籍、创造性视觉 |
| 计算机 | `#55D4CE` | 代码、算法与信息网络 |
| 未知 / 待核验 | `#7B8495` | 模糊与不完整的信息 |
| 主要字体色 | `#F0F3F5` | 标题、旁白、重点标签 |

色彩数量允许随章节变化，但每次变化应有理由。全局镜头中优先使用 2–3 种突出色，其余颜色适当降饱和度。

### 4.3 视觉元素语义

- **光点：** 一个知识概念或一次用户提问。
- **连线：** 有说明的概念关联，不代表模型真实神经连接。
- **脉冲：** 某个主题被关注或某条关联被强调。
- **几何体：** 抽象规律与可解释的概念结构。
- **折叠空间：** 从一个学科转入另一学科。
- **灰色断线：** 资料缺失、认识边界或待核验状态。
- **中央光标：** 人类持续提出问题的能力。

### 4.4 字体与文本

建议采用三套字体角色：

1. **等宽字体：** 命令行、数学表达、坐标和系统信息。
2. **无衬线字体：** 章节标题、标签和用户界面。
3. **具有辨识度的标题字体：** 作品标题与重要文学片段。

文本必须在 1080p 预览下可读。避免在复杂粒子背景上放置大量小字。每个知识节点只展示必要信息，详细解释留给交互网页。

## 五、完整分镜与章节规划

**暂定成片：3 分 30 秒（210 秒）。** 具体音乐节拍和镜头切点在确定配乐后重新量测；下面的秒数为叙事工作时间线，而非最终卡点结果。

| 时间 | 英文章节 | 中文主题 | 主要视觉内容 |
| --- | --- | --- | --- |
| 00:00–00:20 | BOOT | 唤醒 | 黑暗、光标、用户问题、知识核心亮起 |
| 00:20–00:45 | MATHEMATICS | 数学 | 数字、坐标、函数、几何、分形 |
| 00:45–01:10 | PHYSICS | 物理 | 波动、粒子、天体轨道、时空 |
| 01:10–01:35 | LIFE | 生命 | 分子、DNA、细胞、生命之树 |
| 01:35–02:00 | CIVILIZATION | 文明 | 时间轴、建筑、文字、知识传播 |
| 02:00–02:20 | CREATION | 创造 | 文学、音乐、艺术、计算机 |
| 02:20–02:45 | CONNECTION | 关联 | 跨学科网络建立、全片视觉高潮 |
| 02:45–03:10 | UNCERTAINTY | 边界 | 不确定、缺失来源、待验证问题 |
| 03:10–03:30 | DISCOVER | 探索 | 网络回收、光标出现、开放式结尾 |

### 5.1 BOOT — 唤醒（00:00–00:20）

**画面：** 全黑之上出现一枚细小光标。系统逐步建立极简对话窗口，虚构用户输入“你对我们的世界了解多少？”。按下 Enter 后，文字收拢成一个发光点。

**镜头：** 极近景光标 → 界面正面 → 推入光点内部。

**转场逻辑：** 光点延伸出第一条坐标轴，将观众带入数学。

### 5.2 MATHEMATICS — 数学（00:20–00:45）

**画面：** 坐标点延伸出直线、圆、抛物线、正弦曲线、螺旋线和分形结构。公式不作为背景乱飞，而是驱动可见的图形变化。

**重点意象：** 欧几里得几何、函数曲线、黄金螺旋的视觉类比、递归分形。

**转场逻辑：** 函数图线逐渐旋转成为三维轨道。

### 5.3 PHYSICS — 物理（00:45–01:10）

**画面：** 数学曲线成为轨道；轨道上的粒子形成有序系统。波动、光、引力轨迹与尺度变换依次展开。镜头先拉远到宏观天体，随即钻入象征性微观世界。

**科学说明：** 以可辨认的示意图表达科学概念，不把艺术化粒子轨道标为严格的物理模拟。

**转场逻辑：** 微观粒子结合，构成化学分子。

### 5.4 LIFE — 生命（01:10–01:35）

**画面：** 分子结构完成旋转，转换为 DNA 双螺旋；螺旋拆解成细胞、叶脉分枝和生命演化的树状图。

**主要视觉：** 化学结构 → 双螺旋 → 细胞 → 生命之树。

**转场逻辑：** 生命之树的树枝变成文明史的分叉时间轴。

### 5.5 CIVILIZATION — 文明（01:35–02:00）

**画面：** 人类文明时间带铺开，依次闪现代表性建筑剪影、书写载体、地图、科学仪器和印刷物。发光线条连接不同时代与地区的知识交流。

**原则：** 不简单表现为单向的“文明进步阶梯”，而强调多地区、多路径的知识积累与交流。

**转场逻辑：** 历史文献的文字解体，转换为字形、乐谱和计算机代码。

### 5.6 CREATION — 创造（02:00–02:20）

**画面：** 文字变成诗歌排版，诗歌的韵律转化为音符和频谱；频谱继续转化为代码、数字艺术和几何纹样。

**重点：** 同一个核心图形在文学、音乐、艺术和编程媒介之间无缝变化。

**转场逻辑：** 各种图形被吸向同一个知识空间。

### 5.7 CONNECTION — 关联（02:20–02:45）

**画面：** 之前出现的数学、物理、生命、文明和艺术图形全部返回。概念节点被加入网络；真实关联高亮，装饰性粒子形成宇宙般的尺度感。

**跨学科示例：** 傅里叶变换 ↔ 声音信号 ↔ 图像处理；图论 ↔ 交通网络 ↔ 计算机算法；分子结构 ↔ 生命科学。

**高潮镜头：** 相机持续拉远，知识节点形成星图，巨型片名 `THE ATLAS OF KNOWLEDGE` 从概念网络之间浮现。

**构图要求：** 高密度不等于没有焦点。中心必须有清晰主体与视觉路径；避免所有节点同时同等发光。

### 5.8 UNCERTAINTY — 边界（02:45–03:10）

**画面：** 音乐突然减少声部，星图边缘出现灰色节点、缺少来源的关系和未闭合路径；部分线条停在未回答的问题上。

**依次出现三个关键词：**

- `UNKNOWN` — 未知
- `UNCERTAIN` — 不确定
- `VERIFY` — 验证

**表现重点：** 不应将视觉断线解读为对 GPT 某个真实内部知识缺口的测量。观众应理解这是对知识可靠性、时效性和人类认识边界的表达。

### 5.9 DISCOVER — 探索（03:10–03:30）

**画面：** 知识网络回缩成一个小光点，光点落回开场的聊天输入框。新的光标开始闪烁，文字出现：`What would you like to discover?`

**最终镜头：** 固定镜头、简洁字幕、留白、淡出。

**结构闭环：** 从人类提出问题开始，最终回到人类继续探索。

## 六、知识数据与内容生产

### 6.1 数据规模

MVP 阶段建议使用 **40–80 个核验后的示例节点**，最终完整项目采用 **300–500 个精选概念节点**。节点数量是项目自己的策展规模，不代表 GPT 的真实知识总数。

八个一级分类：

1. 数学与逻辑
2. 物理与天文学
3. 化学与材料
4. 生物与医学基础
5. 地理与地球科学
6. 历史与社会科学
7. 语言、文学与艺术
8. 计算机与人工智能

### 6.2 节点模型

示例 `knowledge_nodes.json`：

```json
[
  {
    "id": "fourier-transform",
    "name_zh": "傅里叶变换",
    "name_en": "Fourier Transform",
    "category": "mathematics",
    "summary": "将适用的信号表示为不同频率成分的数学工具。",
    "sources": ["https://example.org/replace-with-verified-source"],
    "verification": "pending"
  }
]
```

`example.org` 是占位符，制作时必须替换为真实、可核验的参考资料。

示例 `knowledge_edges.json`：

```json
[
  {
    "source": "fourier-transform",
    "target": "audio-signal-processing",
    "relation": "applied_in",
    "verified": false,
    "evidence": []
  }
]
```

**正式发布规则：** 未验证的关系不可作为“事实连线”展示；可以先以待核验颜色在开发预览中呈现。关系应尽可能具有明确类型，例如“属于”“依赖”“应用于”“影响”“类比”。

### 6.3 数据生产流程

主题选择 → 节点初稿 → 来源搜集 → 关系标注 → 内容核验 → 数据校验 → 可视化编排。

可使用 GPT 辅助生成候选知识点、摘要和关系草稿，但不能将模型生成内容直接等同于事实。尤其是历史归属、科学定义与专业术语，要结合公开可靠资料验证。

## 七、技术架构与工程目录

### 7.1 推荐技术方案

| 模块 | 推荐技术 | 主要职责 |
| --- | --- | --- |
| 网页预览 | Vite + JavaScript / TypeScript | 开发服务器与预览页面 |
| 二维绘图 | Canvas 2D | 聊天 UI、文字、公式、平面示意 |
| 三维绘图 | Three.js + WebGL | 粒子、关系图谱、空间镜头 |
| 数据 | JSON / TypeScript 类型约束 | 知识节点、镜头、时间轴 |
| 音频分析 | Python 离线脚本 | 起音、节拍、能量等特征提取 |
| 自动导出 | Playwright + FFmpeg | 逐帧导出与 MP4 封装 |
| 自动检测 | Node.js / Python | 帧校验、同步、闪烁、回归对比 |

使用 Three.js 是**本项目建议的扩展方案**，而非声称原仓库依赖 Three.js。原仓库的主要路径为 Canvas 2D + WebGL2。

### 7.3 统一渲染接口

```typescript
interface RenderContext {
  width: number;
  height: number;
  fps: number;
}

// t 为影片时间（秒）；固定资源与固定 t 应生成可复现的画面。
function renderFrame(t: number, context: RenderContext): void {
  // 根据 t 定位当前镜头
  // 计算摄影机、粒子、节点与字幕状态
  // 绘制二维层与三维层
  // 执行后处理合成
}
```

**确定性要求：**

- 镜头状态直接由绝对时间计算，不依赖“上一帧已经运行了什么”。
- 不使用不带固定种子的随机数控制关键对象布局。
- 动画时间以音频 / 全局时间轴为准，不使用未经控制的实际系统时间。
- 字体、图片、着色器在导出之前完成加载。
- 实时互动与离线视频输出采用不同控制入口，但尽量复用绘制模块。

## 八、交互式网页拓展

完成视频后，使用同一知识数据集制作可交互网页。该部分不需要严格绑定影片时间轴，主要提供探索功能。

### 8.1 基本功能

- **旋转与缩放：** 浏览三维知识网络。
- **学科筛选：** 只查看特定知识领域及其直接关联。
- **节点详情：** 显示概念解释、学科、来源和关联节点。
- **关系高亮：** 点击节点后强调与其相连的有效关系。
- **关键词搜索：** 从概念名查找节点并定位相机。
- **故事模式：** 一键按导演定义的镜头路线浏览核心知识。

### 8.2 GPT API 可选功能

例如输入：“为什么傅里叶变换既可以用于音乐，又可以用于图像？”

网页可先定位并高亮：`傅里叶变换 → 声音信号 → 图像处理`，然后在有参考材料的前提下让 GPT 生成解释。

**边界说明：** 这种模式展示的是应用程序自己的知识节点、检索和生成过程，不能宣称能够查看 GPT 模型内部的真实注意力连接或推理轨迹。

## 九、制作流程与工作计划

以上为单人或小团队制作的目标安排，不是保证的工期。开发中应优先保证画面识别性、内容准确性和渲染稳定性。

### 9.1 生产流程建议

1. **策划：** 确认故事、技术边界和章节命题。
2. **美术测试：** 每个学科制作清晰的单幅主视觉，不急于加入复杂运动。

## 十、60 秒最小可行原型（MVP）

完整项目开工前，先制作一个有完整开场与结尾的 60 秒原型，以验证作品最困难的部分——**数学意象、科学意象和知识网络是否能自然变形衔接**。

| 时间 | 画面 | 核心技术目标 |
| --- | --- | --- |
| 00–10 秒 | 提问窗口与知识核心启动 | Canvas 文字和界面动画 |
| 10–25 秒 | 数学公式转为几何与物理轨道 | 几何生成和摄影机变形 |
| 25–45 秒 | 轨道展开成知识节点网络 | 三维布局和连线渲染 |
| 45–60 秒 | 节点组成标题并回到光标 | 音乐同步、粒子编排与合成 |

### MVP 验收标准

- [ ] 浏览器能播放或拖动时间轴预览。
- [ ] 同一帧在固定环境与数据下可重复渲染。
- [ ] 输入任意视频时间能正确获得镜头画面。
- [ ] 公式与节点文字在 1080p 下清楚可读。
- [ ] 重要转场可与音乐拍点同步。
- [ ] 具有至少 40 个可解释、有来源或待核验标记的概念节点。
- [ ] 1080p MP4 能正确导出并播放。
- [ ] 60 秒片段始终有清晰视觉焦点，不依赖无意义的粒子密度。
- [ ] 不使用过量高对比频闪，对潜在高风险视觉变化进行安全检测。

### 优先级建议

**P0：** 时间轴、渲染接口、三种视觉层、完整可导出原型。  
**P1：** 更丰富的学科内容、平滑转场、素材质感、自动分镜。  
**P2：** 三维网页交互、概念搜索、GPT API 解释功能。

### 11.1 交付清单

**视频：**

- 3 分 30 秒左右的完整动画 MV。
- 1080p60 预览版。
- 4K60 最终版。

**代码：**

- 音频预处理与镜头调度工具。
- 知识节点与关联数据。
- 自动视频导出与检查脚本。
- 后续交互网页所需的基础可视化模块。

**文档：**

- 本策划案及 README。
- 逐镜头分镜表 `STORYBOARD.md`。
- 美术风格规范。
- 数据说明与来源表。
- 素材授权与使用清单。
- 制作记录与测试报告。

### 11.2 质量检查要求

| 检查项目 | 目的 |
| --- | --- |
| 分镜覆盖 | 所有章节均有镜头、镜头时间无非预期空档 |
| 随机时间采样 | 不同时间点均能正确渲染 |
| 镜头截图表 | 检查画面密度、主体大小、颜色连续性 |
| 回归测试 | 修改公共模块后避免其他章节画面意外改变 |
| 帧率与同步 | 视频帧、配乐和字幕一致 |
| 视觉安全 | 检查频闪与剧烈高对比变化 |
| 知识来源检查 | 节点、定义和关系有足够可靠依据 |
| 素材许可检查 | 音乐、字体、图片、代码授权范围明确 |

### 11.3 明确的风险与对策

- **风险：概念过于抽象，观众无法理解。** 对策：每章固定一个主视觉和少量可读词语。
- **风险：粒子过密，画面没有焦点。** 对策：近中远景分层、控制高亮数量、预留负空间。
- **风险：强特效遮挡文字。** 对策：信息层优先，背景光效在文字出现时自动减弱。
- **风险：三维渲染性能不足。** 对策：实例化粒子、预计算关系布局、离线高质量输出。
- **风险：知识关系缺乏依据。** 对策：来源标注、关系分级和人工核验。
- **风险：误导观众把演示当成 GPT 内部结构。** 对策：片头或片尾及项目说明标注艺术化知识地图属性。
- **风险：音乐和素材版权。** 对策：使用原创或明确获得授权的配乐与图像。

## 十二、最终创作宣言

《GPT: THE ATLAS OF KNOWLEDGE》希望借鉴程序化视觉叙事的力量，将一个普通提问延伸成跨越数学、物理、生命、人类文明和创造力的探索旅程。

**它不是一份关于 GPT“无所不知”的宣传片，也不是模型真实内部知识结构的截图。**

它希望让人们感受到：知识并不是彼此孤立的答案；不同学科之间有值得被发现的联系。GPT 能够成为探索这些联系的工具，同时仍需要人类进行判断、验证和创造。

> **知识的价值，不只在于被保存，更在于被理解、被连接、被质疑，以及被人类继续探索。**
